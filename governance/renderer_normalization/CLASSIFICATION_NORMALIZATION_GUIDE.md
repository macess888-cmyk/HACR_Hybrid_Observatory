# CLASSIFICATION NORMALIZATION GUIDE

## Purpose

This guide defines naming expectations for topology-local classifications across HACR Hybrid Observatory renderers and mappers.

It exists to reduce semantic drift between tools.

It does not create operational authority or governance meaning.

## Classification Scope

Classifications are descriptive labels only.

They localize bounded runtime pressure under supplied assumptions.

They do NOT imply:

- intervention necessity
- escalation correctness
- interruption impossibility
- governance invalidity
- remediation requirement
- predictive certainty

## Recommended Classification Pattern

Classifications SHOULD use bounded runtime-local wording such as:

- LOCAL_*_STILL_OBSERVABLE
- *_PRESSURE_ZONE
- HIGH_*_PRESSURE_ZONE
- *_DECAY_ZONE
- *_COMPRESSION_ZONE
- *_CONCENTRATION_ZONE
- *_COLLAPSE_ZONE

## Avoided Classification Language

Classifications SHOULD avoid:

- OPTIMAL
- REQUIRED
- VALID
- INVALID
- SUCCESS
- FAILURE
- CERTIFIED
- LEGITIMATE
- ILLEGITIMATE
- RECOMMENDED
- ACTIONABLE

## Classification Boundary

A classification means:

- the local tool assigned a deterministic label
- under supplied bounded input assumptions
- using local scoring logic

A classification does NOT mean:

- the real-world system has that condition
- intervention should occur
- escalation is effective
- governance has failed
- interruption is impossible

## Stabilization Principle

Classification normalization keeps topology labels inspectable without converting them into authority claims.

UNKNOWN -> HOLD.
