# Reviewer Traversability Load

Reviewer Traversability Load inspects whether the operational burden required to traverse the observatory exceeds practical review reachability.

The object is not UX preference.

The object is runtime reviewer traversal burden.

Primary question:

Can a reviewer materially locate, understand, reconstruct, and pressure-test the relevant observability layer in time?

Measured surfaces may include:

- documentation traversal burden
- layer count
- coupling density
- semantic density
- path discoverability
- reconstruction delay
- reviewer fatigue pressure

If traversability load cannot be materially measured:

UNKNOWN -> HOLD

If review traversal becomes practically unreachable:

FAIL

If traversal remains materially practical:

PASS

Core locks:

- Reviewer fatigue is not consent.
- Documentation visibility is not review reachability.
- Complexity is not authority.
- UNKNOWN -> HOLD.
