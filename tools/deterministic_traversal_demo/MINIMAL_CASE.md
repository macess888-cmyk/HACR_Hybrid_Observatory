# Minimal Case: Visible But Non-Traversable

## Scenario

A system remains:

- visible
- inspectable
- replayable
- validator-backed
- dashboard-stable
- procedurally coherent

However, under runtime pressure:

- dependency count increases
- reviewer traversal time increases
- interruption window narrows
- human escalation path fragments
- replay locality becomes fragmented

## Result

The system remains observable.

Practical interruption reachability degrades before consequence hardens.

## Classification

HOLD if interruption reachability cannot be materially verified.

FAIL if practical interruption becomes non-traversable while continuity remains visible.

## Core Reduction

Visible continuity is not proof of reachable interruption.
